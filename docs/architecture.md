# Архитектура: исходные требования и проект решения

## Подтверждённые требования

ArtiosCAD 22.07, Windows 10. Пользователи без административных прав. После настройки взаимодействие только через три группы Outputs, перечисленные в README. Программа выполняется с сетевой папки, без локальной копии EXE. Администратор публикует обновления централизованно. Все результаты выбранной группы сохраняются рядом с ARD с заменой предыдущих файлов.

## Компоненты

1. **Network Launcher** — постоянный сетевой путь, закреплённый в Outputs. Выбирает активную версию из сетевого манифеста. Запускает её с сети и передаёт код завершения.
2. **Export Runtime** — подготовка задания, проверка входов, ACM → DXF, публикация и диагностика. Штатные Outputs ArtiosCAD формируют ACM, PDF и EPS; самостоятельный рендеринг PDF/EPS не планируется.
3. **User Setup** — настраивает Outputs с backup и проверкой временной копии Defaults до замены. Изменение профиля пользователя из учётной записи администратора не должно незаметно настраивать профиль самого администратора.
4. **Build / Publish** — использует конфигурацию из папки config, собирает релиз отдельно и активирует его только после успешной проверки комплекта.

## Обновление с сети

Предложение: `Launcher.exe`, `active-release.json`, `releases/<version>/...`. Все исполняемые файлы остаются на сетевом диске. Администратор может активировать исправленную версию или предыдущую, не перезаписывая исполняемый файл работающего задания. Версия закрепляется за заданием на весь цикл. Старые версии нельзя удалять, пока они используются. Для обновления самого Launcher потребуется отдельное окно обслуживания.

Обычным пользователям достаточно Read + Execute на каталог приложения; право публикации имеет администратор. При недоступности сети запуск завершается понятной ошибкой. Работа без сети не является требованием.

## Связь файлов с текущим заданием

Точное имя и возраст файла недостаточны. Каждое задание получает ID, исходный путь ARD, профиль форматов и собственный рабочий каталог. В манифесте фиксируются входы и состояние обработки. Финализация использует неизменяемые снимки входных файлов. Старый PDF/EPS не может удовлетворить требования нового задания.

Критическая непроверенная часть: каким способом штатные Outputs ArtiosCAD 22.07 могут получать каталог/имя текущего задания и как группа ведёт себя после ошибки первого этапа. В прототипе подтверждается лишь статический каталог C:\CAM, поэтому поддержку динамического пути нельзя считать установленной.

Предпочтительная цепочка: Begin → штатные Outputs выбранного профиля → Finalize. Её допускается внедрять только после проверки передачи контекста и обработки ошибок. Простое добавление Begin не гарантирует безопасность: кратковременный процесс не удерживает блокировку после выхода, а группа может продолжить работу после его ошибки.

Если динамический каталог недоступен, потребуется отдельный режим с фиксированным staging, координатором на весь цикл и проверенной сериализацией штатных Outputs. Такой режим нельзя выдавать за равноценный безопасный вариант без интеграционных испытаний. Автоматический подбор самого свежего файла запрещён.

## Публикация рядом с ARD

Сначала проверить наличие всех обязательных форматов и непустую корректную геометрию. Подготовить полный комплект временных файлов в целевой папке. Под блокировкой целевого задания сохранить предыдущие версии и заменить результаты. Вести журнал для восстановления после ошибки или аварийного завершения. Сохранять входы неуспешного задания для диагностики.

Файловая система не даёт общей атомарной замены нескольких соседних файлов. Журнал, backup и восстановление сокращают риск, но сторонний процесс во время замены может увидеть смешанный комплект. Если downstream-потребителю потребуется строгая целостность, понадобится согласованный маркер готовности либо отдельные каталоги версий. Это ограничение должно быть отражено в документации.

Результаты форматов, не входящих в текущую группу, автоматически не удаляются. Следовательно, после экспорта ACM/DXF рядом может оставаться PDF предыдущего запуска; интерфейс и журнал не должны представлять его как результат текущего задания.

## Геометрия и тестирование

Взять алгоритм прототипа за отправную точку, но отделить парсер ACM и writer DXF от файловой интеграции. Запретить пустую геометрию и молчаливый пропуск неподдерживаемых значимых команд. Ограничения по единицам и инструментам должны быть явными.

До выпуска проверить: все три группы, повторный запуск, одинаковые имена ARD в разных папках, отсутствующий PDF/EPS, старые входы, параллельные задания, блокировки файлов, обрыв сети, аварийное завершение, переключение релиза, кириллицу и пробелы в путях. Геометрию сравнивать с эталоном по координатам и типам объектов. Реальных файлов и доступа к ArtiosCAD сейчас нет; эта проверка остаётся условием производственного выпуска.
