# ArtiosCAD Fast Export 0.1 — проверка пилота

Это тестовый прототип для ArtiosCAD 22.07 / Windows 10. Начинайте с копий ARD в отдельной папке: результаты выбранной группы перезаписываются. У пользователя должен быть один экземпляр ArtiosCAD; параллельный вывод пока не поддерживается. Не запускайте внутренние Outputs FE по отдельности.

## Размещение и настройка

1. Распакуйте весь комплект в сетевую папку, например `\\server\share\ArtiosCADFE`. Сохраните структуру `releases`, EXE и `active-release.json`. Дайте пользователям Read + Execute, администратору — право изменения. Локальные EXE не устанавливаются.
2. В ArtiosCAD сохраните User Defaults хотя бы один раз, затем закройте ArtiosCAD.
3. Под учётной записью пользователя запустите `Setup.exe` **из сетевой папки**. Подключённый сетевой диск преобразуется в UNC при возможности.
4. Выберите существующий `ClientLib\clientdflt.zip` именно этого пользователя. Настройщик проверяет версию 22.07 и создаёт backup рядом. Если нет прав записи, потребуется администратор; при запуске под его учёткой нельзя использовать его LOCALAPPDATA вместо профиля пользователя — выполняйте настройку от целевого пользователя с заранее выданными правами на нужный файл.
5. Откройте ArtiosCAD. Должны появиться три группы:
   - `Plotter (ACM / DXF)`
   - `Plotter (ACM / DXF / PDF)`
   - `Plotter (ACM / DXF / PDF / EPS)`

### Новая установка ArtiosCAD без пользовательских Outputs

Предыдущий SYBOX Bridge и его устройства не нужны. Все определения поставляются в комплекте: Setup добавляет 3 группы и 9 внутренних Outputs. Если в User Defaults нет раздела Outputs или даже Defaults, настройщик создаёт его. Повторная установка обновляет одноимённые записи без дублирования; остальные устройства сохраняются.

Если `clientdflt.zip` ещё не существует, текущий пилот не создаёт весь профиль ArtiosCAD самостоятельно. Сначала под нужным пользователем откройте ArtiosCAD → Defaults, сохраните User Defaults и закройте ArtiosCAD; затем запустите Setup. Добавлять устройства вручную перед этим не требуется. Сам архив и его служебные сведения должен инициализировать ArtiosCAD 22.07. Автоматический первый запуск на полностью новом рабочем месте пока не реализован.

Все локальные файлы находятся в `%LOCALAPPDATA%\ArtiosCADFE`: `Incoming` — промежуточные штатные Outputs; `Jobs\<ID>` — манифест, XML и файлы задания; `Logs` — журнал. `%applocal%` не используется. Настройщик записывает абсолютный путь текущего пользователя в Outputs.

## Проверка по шагам

1. Сохраните тестовый `BOX.ARD`, запустите первую группу. Ожидаются `BOX.ACM` и `BOX.ACM.dxf` рядом с ARD.
2. Измените геометрию, сохраните и повторите. Сравните новую геометрию DXF с ArtiosCAD/штатным эталоном.
3. Запустите вторую группу: дополнительно должен появиться `BOX.pdf`.
4. Запустите третью: дополнительно должен появиться `BOX.eps` с настоящим EPS-содержимым.
5. Проверьте ARD с пробелами и кириллицей, затем одноимённый ARD в другой папке.
6. Проверьте отказ: откройте целевой PDF с блокировкой записи и повторите вторую группу. Ожидается ошибка, сохранённый журнал и возможность восстановить предыдущий комплект. После устранения блокировки закройте ArtiosCAD, выполните `Reset Pilot.cmd`, откройте и повторите.

Для теста отсутствующего PDF можно временно убрать шаг `FE - PDF` из копии второй группы. Даже если старый PDF лежит рядом с ARD, новый вывод должен завершиться ошибкой. После проверки верните группу повторным запуском Setup.

## Что в интеграции пока требует подтверждения

- ArtiosCAD действительно выполняет группу последовательно, дожидается Begin/Finish и передаёт правильный XML. Это основная цель пилота.
- Параметры группы скопированы по структуре из исходного прототипа; корректность нового первого шага Begin ещё не проверена в ArtiosCAD.
- EPS экспериментален: использованы `CamDriverName=EPSF` и `TUNE.EPSF.TXT`. Если драйвер не выбирается, откройте Defaults → Outputs → `FE - EPS (pilot)` и выберите штатный EPSF/Illustrator и tuning-файл вашей установки. Пришлите сохранённый XML Defaults для уточнения шаблона. Переименование PDF в EPS не допускается и проверяется.
- PDF/EPS проверяются по сигнатуре, PDF также по завершающему маркеру; это не полная проверка документа или содержимого.
- Парсер ACM намеренно строгий. При новой неподдерживаемой команде он остановится и сохранит исходный файл. Это повод уточнить поддержку по образцу, а не отключать проверку.
- Пилот очищает отдельный входной слот до задания и запрещает продолжение незавершённой сессии. Это не доказанная защита от всех сценариев параллельного/вложенного вывода; для них требуется следующий этап интеграции.

## После ошибки и откат

Закройте ArtiosCAD и запустите `Reset Pilot.cmd`, затем повторите вывод. Сброс архивирует запись сессии, а не удаляет данные диагностики. Перед новым выводом старые входы перемещаются в `Jobs\<ID>\PreviousInputs`. Каталог C:\CAM старого прототипа не используется.

Для полного отката закройте ArtiosCAD, сохраните текущий clientdflt.zip отдельно и восстановите нужный `clientdflt.zip.before-fe-*.bak` под именем `clientdflt.zip`. Точный путь backup указан в `%LOCALAPPDATA%\ArtiosCADFE\last-setup.txt`. Учтите, что восстановление полного backup также откатывает последующие изменения других Defaults.

Рядом с ARD создаётся служебный каталог `.artioscad-fe-<hash>` с блокировкой и журналом последней публикации. Не удаляйте его `pending` при ошибке: там могут находиться резервные копии для восстановления. Следующий вывод того же ARD сначала пытается восстановить незавершённую транзакцию.

Обычная файловая система не заменяет несколько файлов одной атомарной операцией. При сбое приложение восстанавливает старые версии, а при невозможности восстановления сохраняет журнал и прекращает публикацию. Не передавайте комплект дальше, пока вывод не завершился без ошибки.

Форматы вне текущей группы не удаляются: после группы ACM/DXF старый PDF/EPS может остаться рядом, но не является результатом этого запуска.

## Что прислать по результатам

- Какую группу запускали и что получилось.
- Текст ошибки, если она была.
- Лог и `job.json`, `begin.xml`, `finish.xml` проблемного задания.
- Если возможно, входной ACM и полученный/эталонный DXF.

Данные диагностики содержат пути и сведения о чертеже: передавайте их приватно, не публикуйте рабочие файлы в публичном репозитории. Открыть локальный каталог можно через `Open Diagnostics.cmd`.

## Сборка и обновление администратором

В исходниках: запустите `Build.cmd`; дополнительных NuGet-пакетов и SDK не требуется, используется компилятор .NET Framework 4.x из Windows. Сборка включает автоматические проверки. Путь готовой папки записывается в `artifacts\latest-build.txt`.

Для настройки путей скопируйте `config\publish.example.json` в `config\publish.local.json`, задайте реальный UNC и версию. Сборка: `Build.cmd -Config config\publish.local.json`. Публикация: `powershell -NoProfile -File scripts\Publish.ps1 -BuildDirectory "<папка сборки>" -Config config\publish.local.json`.

Релизы размещаются отдельно. Изменение `active-release.json` выбирает версию для новых заданий; Finish старается использовать версию, выбранную Begin. Не меняйте localRoot между версиями во время активных заданий. Не удаляйте старые версии, пока задания не завершены. Изменение самих корневых загрузчиков требует остановки вывода и окна обслуживания.

Основа EPS-настройки: [документация Esko о форматах экспорта и tuning EPSF](https://docs.esko.com/docs/en-us/artioscadenterprise/18/userguide/en-us/common/ac/topic/UG1_Introduction_id307063UON27.html). Точная сериализация EPSF для 22.07 должна быть проверена на рабочей установке.
